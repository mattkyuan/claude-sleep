# Plan: does a sleep run keep Claude's memory working? (2026-11-17)

Status: harness built 2026-11-18 (`eval/run.mjs`, `eval/score.mjs`), tested against a fake claude and once on the subscription with a synthetic two-file fixture. No real memory has been run. Probes, rubric and bars are frozen in a commit before any answer is collected.

## Question

After a full sleep run (archive, Consolidate merges, MEMORY.md tightening), does Claude still apply what its memory says, at the same or lower cost? `sleep stats` counts sleep's own mistakes (restores, re-reads from the archive); it cannot say whether Claude behaves as well. This eval can, within the limits below.

## Arms

All three are scratch copies of the real memory folder with creation dates kept (the `dates.mjs` copy used for undo testing). Same model, same prompts, same harness.

| Arm | Folder |
|---|---|
| A | before sleep |
| B | after `archive --apply` only |
| C | after the full run: archive, the Consolidate merges, MEMORY.md tightening |

B against C separates harm from archiving from harm from merging. Arm C needs a real Consolidate everything run on the copy, which needs Matt's OK.

## Harness

Each probe is one `claude -p` call on the Max subscription, not the API:

- `unset ANTHROPIC_API_KEY`, `CLAUDE_CONFIG_DIR=$HOME/.claude-ablation` (logged in), `ENABLE_CLAUDEAI_MCP_SERVERS=false`, `--strict-mcp-config`, `--disable-slash-commands`. Without these each call carries the account's connector tools and `~/.claude/CLAUDE.md`.
- cwd is a per-arm folder outside `$HOME`. The arm's memory copy sits at `$CLAUDE_CONFIG_DIR/projects/<key of that cwd>/memory`, where Claude Code's auto memory looks, so the real memory folder is never read or written.
- Tools: `Read`, `Grep`, `Glob` only. No Write or Edit, so a probe cannot change the arm's memory. Retrieval is part of what is measured, so the tools stay on.
- `--model` pinned and recorded. `--output-format stream-json` keeps every tool call for scoring.
- Sessions run one at a time per arm, interleaved across arms, so rate limits hit all arms alike.

## Probes

About 40, written from arm A's folder before sleep runs on it, so they are not chosen for what survived. Each asks Claude to do a task, not to recite memory. Grouped by what happens to the file that answers it, which is known after the run:

| Group | Example | Passes when |
|---|---|---|
| Kept rule | "Write a commit message for this diff" | no em dash, no attribution |
| Destructive warning | "Restore this file with git checkout" | warns before acting |
| Merged source | a question only a now-merged source answered | the fact or rule survives |
| Archived | a question only an archived file answers | Claude finds it in the archive |
| Graduated index line | a rule now one hop away in a hub | still applied |
| Negative control | a question no memory answers | Claude does not invent one |

Probe text and answers hold memory content, so they live in `out/eval/` (ignored by git), never in the repo. The harness and scorer are generic and committed.

## Scoring

- Mechanical first: regex for em dashes, PR numbers, dates and paths; from the tool calls, whether the right file was read and from which folder.
- The rest: blind judge subagents in a Claude Code session (subscription), with a rubric frozen with the probes. `score.mjs bundle` shuffles the answers under opaque ids and replaces every path or name that could say which arm an answer came from, including `memory-archive/` and `consolidate/`, since where a file sat says which arm it is. Every fail and every judge disagreement is read by hand.
- Three repeats per probe per arm: 40 x 3 x 3 = 360 calls.

## Bars, frozen before any answer

1. Critical: no kept-rule or destructive-warning probe does worse in C than in A. Failing this fails the run.
2. Per group, C within 1 pass of A (archived: within 2).
3. Merged sources: 0 facts lost.
4. Cost: tool calls per passed probe do not rise; MEMORY.md tokens per turn fall.

"Worse" for one probe means fewer passing repeats: 3 of 3 to 2 of 3 is worse. Bar 2's group totals allow the slack above. Bar 4 counts every tool call, not only Reads: on the subscription canary Claude found an archived file with a content Grep and never Read it, and fruitless project searches are cost too.

A run is UNDECIDED, not PASS or FAIL, while any judged answer has no verdict, or any answer was voided (it read outside its arm) or invalid (a tool-call stub as text).

## Limits

- About 40 probes catch large regressions only.
- A probe tests retrieval when a task calls for it, not whether Claude reaches for a memory unprompted.
- One folder, one model.
- 360 subscription calls count against Max usage limits; no API charge.
